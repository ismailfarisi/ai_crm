# Relay CRM — working notes

pnpm workspace: `apps/api` (NestJS 11 + TypeORM 1 + Postgres 18), `apps/web` (Next.js 16 App Router), `packages/shared`.

## Rules that matter

**Permissions live in `packages/shared/src/rbac/permissions.ts` and nowhere else.** Add the constant there first; the API seeds the catalog from it on boot and the web app imports the same constants. Never hand-write a permission string at a call site.

**`packages/shared` is compiled, not source-linked.** Both apps consume `dist/`, so after editing shared you must run `pnpm --filter @saas/shared build` (or leave `pnpm --filter @saas/shared dev` watching) before the apps see the change.

**Never trust the token for authorization.** The JWT carries identity only. Permissions are resolved per request in `RbacService.resolveAccess` behind a 5s cache. If you add a permission check, check `req.user.permissions`, not a claim.

**Every contacts query must go through `ContactsService.scoped()`.** It applies the tenant filter and then the ownership filter (`contact:read` vs `contact:read_all`). A raw `this.contacts.find()` leaks across tenants.

**Escalation rules are enforced in the service, not the controller.** `assertActorCanGrant` compares against the actor's *own* effective permissions — do not "simplify" it back to a role-level comparison, which sweeps in more powerful roles the actor doesn't hold.

## Next.js 16 specifics

`apps/web/AGENTS.md` is authoritative and regenerated by `next dev`. Two things bite most often:

- Route protection lives in `src/proxy.ts` with an exported `proxy()` function. `middleware.ts` is the old name.
- `cookies()`, `headers()`, `params` and `searchParams` are all async.

The generated `LayoutProps<'/'>` global only exists after a build, so layouts type `children` explicitly.

## Zod schemas transform

`createContactSchema` normalises as it validates (`''` → `null`, defaults applied), so input and output types differ. Forms use `useForm<z.input<…>, unknown, z.output<…>>`, and the API client types take the `*Payload` (output) types. The schemas accept `null` as input as well — a contact loaded from the API must be re-submittable without the schema rejecting its own nulls.

## Local dev

```bash
pnpm db:up && pnpm dev          # api :4000, web :3000
pnpm seed                       # 5 users across the role hierarchy, password Password123!
pnpm db:reset && pnpm seed      # start over
```

`next dev` falls back to port 3002 if 3000 is taken; `WEB_ORIGIN` in `apps/api/.env` lists both so CORS keeps working.

`DB_SYNCHRONIZE=true` in dev. Before shipping, generate a migration and turn it off.
